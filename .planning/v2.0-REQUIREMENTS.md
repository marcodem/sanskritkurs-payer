# Anforderungen (Requirements) - Milestone v2.0

## 1. Static Embedding Pipeline (SRCH-E)
- [ ] **SRCH-E1**: Node.js Script zur Extraktion von Text-Chunks (Sektionen/Grammar-Boxes) aus den 14 Sprachen.
- [ ] **SRCH-E2**: Vektorisierung der Chunks mit einem lokalen Embedding-Modell (z.B. Xenova/transformers.js) während des `npm run docs:build`.
- [ ] **SRCH-E3**: Generierung statischer `vector-index-[lang].json` (oder `.bin`) pro Sprache.

## 2. Client-side Semantic Search (SRCH-C)
- [ ] **SRCH-C1**: Neues Such-Interface ("KI-Suche") in VitePress integriert.
- [ ] **SRCH-C2**: Automatisches Laden des Embedding-Modells (~25MB) im Browser via Web Worker.
- [ ] **SRCH-C3**: Cosinus-Ähnlichkeits-Berechnung in JavaScript (lokal) um die Top-K Chunks zur Nutzerfrage zu ermitteln.

## 3. WebGPU LLM Answer Generation (SRCH-L)
- [ ] **SRCH-L1**: Einbindung von `@mlc-ai/web-llm` und Bereitstellung eines 2B/4B IT-Modells (z.B. Gemma 2B IT).
- [ ] **SRCH-L2**: RAG-Prompt-Generierung: Einspeisen der Top-K Chunks als System-Context in den Chat.
- [ ] **SRCH-L3**: Streaming-UI ("ChatGPT-Stil") für die generierte Antwort.
- [ ] **SRCH-L4**: Anzeige und Verlinkung der referenzierten Lektionen/Chunks unterhalb der Antwort.

## 4. Provider/Adapter & Fallbacks (SRCH-F)
- [ ] **SRCH-F1**: Provider/Adapter-Architektur (`AIService`, `LLMProvider`) aus dem Zentauri v2.0 Konzept.
- [ ] **SRCH-F2**: Fallback-Provider (z.B. OpenRouter API) für Geräte ohne WebGPU.
- [ ] **SRCH-F3**: Caching des LLM-Modells (~1.5GB) über den Service Worker (mit Opt-In/Progress-Bar in den Settings).
